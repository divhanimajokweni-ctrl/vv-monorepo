### Step 2: Supabase — two projects (45 minutes)

Go to supabase.com. Create **two separate projects**: `ubuntu-pools-dev` and `ubuntu-pools-prod`. Never share a database between dev and prod.

In each project, run this schema in the SQL editor:

```sql
-- Users / auth handled by Supabase Auth automatically

-- Pools
CREATE TABLE pools (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  target_amount DECIMAL(12,2) NOT NULL,
  current_amount DECIMAL(12,2) DEFAULT 0,
  status TEXT DEFAULT 'open', -- open | funded | active | closed
  created_at TIMESTAMPTZ DEFAULT NOW(),
  pool_round INTEGER DEFAULT 1
);

-- Pool memberships
CREATE TABLE pool_members (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  pool_id UUID REFERENCES pools(id),
  user_id UUID REFERENCES auth.users(id),
  stake_amount DECIMAL(12,2) NOT NULL,
  joined_at TIMESTAMPTZ DEFAULT NOW(),
  status TEXT DEFAULT 'active', -- active | withdrawn | pending
  UNIQUE(pool_id, user_id)
);

-- Contributions / transactions
CREATE TABLE contributions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  pool_id UUID REFERENCES pools(id),
  user_id UUID REFERENCES auth.users(id),
  amount DECIMAL(12,2) NOT NULL,
  type TEXT NOT NULL, -- stake | redirect | withdrawal | payout
  reference TEXT, -- PayShap / EFT reference
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Waitlist
CREATE TABLE waitlist (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email TEXT UNIQUE NOT NULL,
  name TEXT,
  phone TEXT,
  stokvel_coordinator BOOLEAN DEFAULT FALSE,
  joined_at TIMESTAMPTZ DEFAULT NOW(),
  converted BOOLEAN DEFAULT FALSE
);

-- Row Level Security — users see only their own data
ALTER TABLE pool_members ENABLE ROW LEVEL SECURITY;
ALTER TABLE contributions ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users see own memberships" ON pool_members
  FOR ALL USING (auth.uid() = user_id);

CREATE POLICY "Users see own contributions" ON contributions
  FOR ALL USING (auth.uid() = user_id);
```

Save the two connection strings — you'll need them as env vars.

### Step 3: Railway — Node.js API (30 minutes)

Go to railway.app. Connect your GitHub repo. Create two services: one pointing to `dev` branch, one to `main`.

Your `package.json` needs a start script:
```json
{
  "scripts": {
    "start": "node dist/index.js",
    "dev": "ts-node-dev src/index.ts",
    "build": "tsc"
  }
}
```

Create a `railway.toml` in your repo root:
```toml
[build]
builder = "NIXPACKS"

[deploy]
startCommand = "npm start"
restartPolicyType = "ON_FAILURE"
restartPolicyMaxRetries = 3
```

Set these environment variables in Railway (for each service separately):

```bash
# Production service env vars
DATABASE_URL=postgresql://...  # from Supabase prod
SUPABASE_URL=https://xxx.supabase.co
SUPABASE_SERVICE_KEY=eyJ...    # service role key (not anon)
JWT_SECRET=your-secret-min-32-chars
NODE_ENV=production
PORT=3000
CORS_ORIGIN=https://ubuntupools.app

# Dev service env vars — same keys, different values
NODE_ENV=development
CORS_ORIGIN=https://dev.ubuntupools.app
DATABASE_URL=postgresql://...  # from Supabase dev
```

### Step 5: Resend — email for waitlist (15 minutes)

Go to resend.com. Free tier sends 3,000 emails/month — enough for 200 people many times over.

```bash
npm install resend
```

```typescript
// src/services/email.ts
import { Resend } from 'resend';

const resend = new Resend(process.env.RESEND_API_KEY);

export async function sendWaitlistConfirmation(email: string, name: string) {
  await resend.emails.send({
    from: 'Ubuntu Pools <hello@ubuntupools.app>',
    to: email,
    subject: 'You\'re on the Ubuntu Pools waitlist — umuntu ngumuntu ngabantu',
    html: `
      <h2>Sawubona ${name},</h2>
      <p>You're confirmed on the Ubuntu Pools waitlist. 
         We're launching our first pool in Gqeberha soon.</p>
      <p>We'll notify you when your pool is ready to join.</p>
      <p>— Mino & the Ubuntu Pools team</p>
    `
  });
}
```

### Step 6: Convert the waitlist (the actual work)

Once deployed, you need a simple API endpoint to import your 200 people:

```typescript
// POST /api/waitlist/import  (admin only — call this once)
router.post('/waitlist/import', requireAdmin, async (req, res) => {
  const { emails } = req.body; // array of { email, name, phone }
  
  for (const person of emails) {
    await supabase.from('waitlist').upsert(person, { onConflict: 'email' });
    await sendWaitlistConfirmation(person.email, person.name);
  }
  
  res.json({ imported: emails.length });
});
```

## What the 200 people need on launch day

Before you send a single email, make sure these four things work end to end in production:

1. They can open `ubuntupools.app`, register with email, and get a confirmation email
2. They can log in and see a dashboard showing their pool status
3. They can see the pool they've been assigned to (even if it says "opening soon")
4. There is a clear next step — a button, a WhatsApp link, a date — so they don't arrive and bounce
